# 赛马（平行多路尝试）

同一个任务，在 2–4 个互相独立的 git worktree 里，用不同的模型、思考强度或附加提示同时跑；全部结束后并排比较客观证据，一键采用其中一条，其余丢弃。

## 使用方式

1. 在输入框的模式菜单（Agent / Plan / Goal）里选择「赛马」。赛马不是新的对话模式，只是一个启动动作；当前对话的模式不变。
2. 设置对话框里写任务（默认取输入框内容），为每条赛道选择模型、思考强度和可选的附加提示，也可以填一条「统一验证」指令（例如 `pnpm test`）。非 git 仓库、没有任何提交时无法开始。
3. 开始后右侧 Workbench 打开「赛马」分页，每条赛道一张卡片，实时显示状态、耗时、token、改动、验证结果。
4. 所有赛道结束后，赛马进入「可比较」。点击某条赛道的「采用这条」，确认后把它的改动放进主工作区的暂存区，其余赛道的 worktree 与分支全部删除。提交由你自己完成。
5. 「全部丢弃」会停止所有赛道并清理 worktree 与分支。

赛道对话是后台对话，不会抢占当前选中的对话或工作区；「打开对话」可以随时查看某条赛道的过程。

## 比较的证据

全部是事实，不调用模型，也不做加权评分、不自动挑胜者：

| 证据 | 来源 |
| --- | --- |
| 耗时 | 赛道开始到结束的墙钟时间。 |
| token | 根对话加所有子代理的用量合计。 |
| 改动 | 赛道结束后在其分支上提交，再对 `startSha` 取 `--numstat`（文件数、增、减）。没有任何改动的赛道不可采用。 |
| 统一验证 | 设置了验证指令时，全部赛道结束后由主进程依次在每个 worktree 里执行（并发 1，耗时可比）。有 10 分钟超时，输出脱敏并只保留末尾 4000 字符。 |
| agent 自报验收 | 面板读取赛道对话，用与聊天里「验收」相同的函数推导通过数与待确认数，可点开完整验收。主进程不另存。 |

徽章只标事实上的最优（最快、token 最少、改动最小、唯一通过验证）：只在所有赛道结束后显示；只有一条赛道具备该指标，或所有赛道数值相同，则不加；并列时都加。

## 采用与清理

- 只有赛马处于「可比较」时才能采用，并且主工作区不能有已追踪文件的未提交变更（未追踪文件不影响）。
- 采用使用 `git merge --squash`，变更留在暂存区。发生冲突时会 `git reset --merge` 还原，赛马仍是「可比较」，可以改选其他赛道。
- 成功后其余赛道的 worktree 与 `vela/race-*` 分支被强制删除；赛道对话保留，方便事后查看。清理失败时赛马标为已采用并提示残留，可点「重试清理」。
- 赛道从启动时的 `HEAD` 开始，**不包含**主工作区未提交的改动；设置对话框会提示。
- 赛道在后台无人值守运行。sandbox 模式为 ask 时需要授权的操作会一直等待你批准，对话框里有提醒；默认取当前模式，不会悄悄放宽。

## 存储与恢复

- 赛马记录保存在 `~/.vela/races.json`（原子写入）；worktree 位于 `~/.vela/worktrees/vela-race-<id>-<n>`，分支为 `vela/race-<id>-<n>`。
- 读取时严格校验分支名、SHA 和 worktree 路径，被改过的记录不会让应用去删除别的分支或目录。
- 应用退出时仍在进行的赛马与赛道，下次启动标为「已中断」；它们的 worktree 里可能留有未提交的改动，可以丢弃，或打开赛道对话查看。
- 同时进行的赛马最多 2 场，每场 2–4 条赛道，最坏同时有 4 × 2 个 agent 会话，请留意供应商限速与费用：赛马会消耗约 N 倍 token。

## 实现位置

- `packages/shared/src/race.ts`：类型、IPC 通道、限制常量、`parseRaceDraft`、`raceBadges`。
- `packages/agent/src/runtime.ts` 的 `runLane` 与 `getLaneStats`：创建后台赛道对话并等到包括子代理在内全部空闲。
- `packages/workspace/src/git-squash.ts`：提交 worktree 改动、统计 diff、`squashMergeBranch`。
- `apps/desktop/src/main/race-service.ts`、`race-host.ts`、`race-verify.ts`：编排、IPC、统一验证。
- 渲染层：`RaceSetupDialog.tsx`、`RacePanel.tsx`、`race.css`、`hooks/useRaces.ts`、`composer/ModeChip.tsx`。

## 验证

- `pnpm --filter @vela/desktop test:race`：赛马服务（建赛道、取证、验证、采用、冲突、恢复、被篡改的记录）、`runLane` 与 git squash 的单元测试。
- `apps/desktop/test/race-ui.mjs`：真实 Electron 里检查面板事实、徽章、采用确认、冲突提示、暗色与窄宽度、设置对话框；纳入 `pnpm test:ui`。预览页为 `apps/desktop/test/race-preview.html`。

## 不包含

- 第一个通过就自动停掉其余赛道、自动评分或 LLM 裁判。
- 把赛马结果接入任务配方的效果比较。
