# 侧边聊天

状态：已在 1.1.10 发布。

侧边聊天是工作面板里的轻量对话：只和模型聊天，不提供任何 Agent 工具，带入长期记忆。适合在主对话运行时顺手问个概念、核对思路，而不打断或污染主对话的上下文。

## 使用

- 工作面板标签栏的 `+`（或 ⌘T）打开新标签页，选择「侧边聊天」。每个项目只有一个侧边聊天标签，打开后先进入**本项目的聊天列表**，参考即时通讯应用：
  - 每行是一段聊天：名字取第一条消息，下面是最后一条消息的预览，右侧是时间（今天显示时刻，昨天，一周内显示星期，更早显示日期）；按最近更新排序。
  - 顶部搜索框按名字和全部消息搜索（不区分大小写），命中正文时预览改为命中片段并高亮；`Esc` 或 × 清除搜索。
  - 右上角「新聊天」新建一段并进入；点某一行进入那段聊天。
  - 鼠标悬停时行右下角出现垃圾桶，点一下变成「确认删除」，3 秒内再点才会删除。
  - 正在回复的聊天在预览处显示「正在回复…」。
- 聊天界面左上角的返回箭头回到列表；返回时仍在回复的聊天继续在后台接收并保存，不会被中断。右上角垃圾桶同样需要二次确认，删除后回到列表。
- Enter 发送，Shift+Enter 换行；回复中可以停止，已收到的部分保留并标记「已停止」。
- 失败时显示错误，「重试」从最后一条用户消息重新请求。
- 关闭标签会停止仍在进行的回复，已保存的聊天保留；再次打开标签回到列表。
- 输入框下方可以单独选择模型和推理强度，与主输入框是同一套控件；选择只作用于侧边聊天，不改动主对话。新开的聊天沿用上一次的选择（保存在界面存储 `vela.sideChat.model`），没有记录时沿用打开那一刻主对话的模型与推理强度。在这里添加自定义模型只登记并在侧边聊天里选中。
- 侧边聊天按项目保存，见下文「持久化与项目互通」。切换到同一项目的另一个对话，标签、列表和内容原样保留；切换到别的项目，只显示那个项目自己的聊天。下一次发送按新的主对话带入记忆，模型保持侧边聊天自己的选择。
- 在对话里选中文字送进侧边聊天：标签正停在某段聊天里就加入那段聊天（可以攒多张引用），否则新开一段聊天。

## 能力边界

- 没有工具：不能读写文件、运行命令、浏览网页，也看不到主对话。系统提示词要求模型在需要这些能力时说明并建议回到主对话，不假装执行过。
- 只读记忆：不提供 `memory_update`，要求记住的内容需在主对话或设置页「记忆」里保存。
- 不写入对话：侧边聊天的历史单独保存，不写入任何对话记录，也不计入对话的轨迹和用量统计。

## 持久化与项目互通

- 历史保存在资料目录的 `side-chats/` 下，每个项目（工作区目录）一个文件，文件名是项目路径的哈希；没有工作区的对话共用一份。重启应用后仍在。
- 同一项目下的所有对话共用这份聊天列表，聊天不属于某个对话窗口。每个项目最多保留最近更新的 50 段，每段最多 400 条消息。
- 保存时机：发送后立即保存用户消息，回复结束（完成、停止、出错）后再保存一次。回复中途退出应用，用户消息不会丢。新建后一条消息都没发的聊天不会保存，也不会出现在列表里。
- 删除（列表或聊天界面）同时删除磁盘上的记录；删除时仍在回复的请求会被取消，收尾时不会把它写回。
- 多个窗口各自读写同一份文件，没有实时同步；以最后保存的为准。

## 能力边界补充

- 模型和推理强度的选择仍是全局记住的偏好（`vela.sideChat.model`），不随项目保存。

## 模型与记忆

`packages/agent/src/runtime.ts` 的 `sideChat`：

- 模型：界面总是发送侧边聊天自己选的模型；请求未指定时依次用当前主对话（`conversationId`）选定的模型和设置里的默认模型。不可用时报错（例如「这个模型还不能使用，请先登录或填写密钥」）。
- 推理强度：`SideChatService` 用 `clampThinkingLevel` 按模型支持范围调整，`off` 或不支持推理的模型不传 `reasoning`；结果里返回实际使用的强度。界面切换模型时，原强度不受支持则取不超过它的最高一档（`side-chat-model.ts` 的 `sideChatModelInfo`）。
- 记忆：「启用记忆」开启时，按当前主对话自己的工作区用 `memoryTargetsFor` 加载全局与项目记忆，与主代理同一套规则（`hasWorkspace` 为 false 只加载全局）；没有主对话时只加载全局。正文经 `memoryContextBlock` 以相同标签注入系统提示，项目记忆在前。关闭时不加载。
- 每次发送都重新读取记忆文件，外部编辑在下一条消息生效。
- 顶部显示记忆状态（已带入全局 / 项目、没有可带入的记忆、记忆已关闭），悬停可看来源路径。

## 历史与请求

- 每次发送完整历史；`packages/agent/src/side-chat.ts` 的 `sideChatHistory` 从最新往前保留约 20 万字符，最后一条用户消息始终保留，开头不留助手消息。
- 请求经 `parseSideChatRequest` 校验：请求 ID、对话 ID 格式、语言、角色、单条长度和条数，最后一条必须是非空用户消息。
- `SideChatService` 用 `ModelRuntime.streamSimple` 发起一次不带 `tools` 的流式调用，按 `requestId` 支持中途停止。

## 实现位置

| 位置 | 内容 |
| --- | --- |
| `packages/shared/src/side-chat.ts` | 请求、结果、流式事件与 `SideChatApi` 契约。 |
| `packages/agent/src/side-chat.ts` | 请求校验、系统提示词、历史裁剪、流式调用与停止。 |
| `packages/agent/src/runtime.ts` 的 `sideChat` / `cancelSideChat` | 模型选择与记忆加载。 |
| `apps/desktop/src/main/session-host.ts` | `side-chat:send` / `side-chat:cancel` IPC，增量只发回发起请求的窗口。 |
| `apps/desktop/src/main/side-chat-store.ts` | 按项目读写 `side-chats/`：校验、规整、原子写入、损坏文件视为空。 |
| `apps/desktop/src/main/side-chat-host.ts` | `side-chat:threads-list` / `-save` / `-remove` IPC。 |
| `apps/desktop/src/renderer/App.tsx` 的 `openSideChatTab` | 每个项目一个标签，按项目过滤；选中文字送来的引用先放进标签的 inbox。 |
| `apps/desktop/src/renderer/components/SideChatPanel.tsx` | 标签内容：聊天列表（搜索、新建、删除）与列表/聊天之间的切换；回复中的聊天保持挂载。 |
| `apps/desktop/src/renderer/components/SideChatView.tsx` | 一段聊天：消息列表、输入、停止、重试、返回与删除，并在关键节点保存。 |
| `apps/desktop/src/renderer/components/ConfirmDeleteButton.tsx` | 二次确认的垃圾桶按钮。 |
| `apps/desktop/src/renderer/components/side-chat-model.ts` | 请求历史、重试范围、模型选择的记忆与推理强度调整、记忆状态文案、聊天名字/预览/搜索/时间标签的纯逻辑。 |

## 验证

```sh
pnpm --filter @vela/desktop test:side-chat      # 校验、提示词、历史裁剪、流式、推理强度、停止、错误、界面模型与项目历史存储
pnpm --filter @vela/desktop test:side-chat:ui   # 真实 Electron：聊天列表与搜索、返回列表、后台回复、删除、关闭后恢复、打开标签、独立选择模型与推理强度、流式显示、记忆状态、停止、重试、跟随主对话、窄宽度、关闭即停止、恢复已保存历史、五种语言
```

UI 检查使用内存夹具代替模型和主进程，没有覆盖真实模型请求，也没有覆盖真实磁盘读写（后者由 `side-chat-store.test.ts` 覆盖）。
