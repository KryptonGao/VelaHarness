日期：2026-10-25。

## 3. 新功能构想（按优先级）

价值评估看三点：用户感知强度、与现有模块的衔接成本、是否强化 Vela 的差异化（透明、可验证、可比较）。

### P0：补齐基础扩展面

**1. 生命周期 Hooks**  
事件：`PreToolUse`、`PostToolUse`、`Stop`、`SessionStart`、`PreCommit`。处理器先做命令型，输入输出为 JSON，可放行、拒绝或追加上下文。配置分全局与项目，项目配置沿用 MCP 的项目信任确认。  
衔接：权限闸门已集中在 `sandbox-tools.ts`，可在同一处挂载；轨迹视图可直接显示 Hook 的触发与耗时，这是别家没有的可观测性。

**2. 内置斜线命令**  
把 `/model`、`/effort`、`/mode`、`/compact`、`/review`、`/handoff`、`/race` 做进现有 `slash-picker.ts`，与 Skill、配方并列分组。成本低，立刻补齐「键盘党」体验。

**3. 审查 Agent（`/review`）**  
对工作区 diff、暂存区或指定提交，用只读子代理分维度审查（正确性、安全、测试覆盖），结果以行级评论形式写回「变更」面板，可一键转成修复任务。分 Quick / Standard / Deep 三档，对应不同子代理数量与思考强度。  
衔接：复用 `explore` 子代理、`pr-review-response` 的回写能力与成果验收的证据结构。

### P1：延展工作的时间与空间

**4. 插件包**  
一个目录打包 Skill、子代理定义、Hooks、MCP 配置与斜线命令，带 manifest 与版本，从本地目录或 Git 仓库安装，沿用 Skill 的同名优先规则。是 Hooks 与自定义命令的分发载体，应排在它们之后。

**5. 聊天软件远程触发**  
先做飞书与 Telegram（微信接入门槛高，列为后补）。机器人把消息转成「收件箱」事项，由常驻 Agent 受理，结果与审批请求回推到聊天。  
衔接：Agent Inbox 的「先落盘后通知」、委派审批与后台运行已经具备，主要工作是适配器与账号绑定，不用重做 Agent 链路。必须把「谁能触发、能做什么」收紧到只读加白名单操作，高风险仍回桌面审批。

**6. 定时任务复用线程**  
为定时任务增加「续接上次对话」选项，保留上下文，适合日报、巡检类任务。改动集中在 `scheduled-task-service.ts`。

**7. SSH 远程工作区**  
把环境管理器里的「远程」占位落地：连接 SSH 主机，文件、终端与 Git 走远端，Agent 工具在远端执行。复杂度高（路径、文件监视、检查点存储位置都要重新考虑），建议先做只读浏览加终端，再做完整执行。

### P2：差异化与拓展

**8. 跨对话用量看板**  
汇总 Token、费用估算、缓存命中率与模型分布，按项目与时间切片。数据已写在轨迹里，主要是聚合与界面。

**9. 赛马结果沉淀为模型推荐**  
把历次赛马的耗时、Token、验证通过率累积成按任务类型的统计，在新赛马或选模型时给出事实性参考。强调只展示证据，不自动选择，延续赛马的原则。

**10. 空闲时段任务**  
机器空闲、接通电源时执行用户挂起的低优先级任务（依赖升级检查、测试补全草稿）。结果只进收件箱，不改主工作区。

**11. 语音输入**  
输入框听写，先用系统听写能力，避免引入模型依赖。

**12. Computer Use**  
操控其他桌面应用，需要系统辅助功能权限与逐应用授权，风险与审批设计远大于收益，当前不建议。

**13. 多平台**  
Windows 与 Linux 打包。需要处理更新器、签名与 Shell 路径，是独立的工程项目，需单独评估。

## 4. 建议的第一批

1. 内置斜线命令（几天可完成，立刻可见）。
2. 生命周期 Hooks（打开后续插件与自动化的口子）。
3. 审查 Agent（最贴近日常使用，且能放大现有变更面板）。

其后按 P1 顺序：插件包 → 聊天软件触发 → 定时任务续接线程。
