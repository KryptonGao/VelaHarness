# Vela Remote Control 产品需求文档

**状态：** 方案稿；本文描述的远程服务、移动端网页和 Tailscale 配置流程均尚未实现。
**日期：** 2026-11-11。
**交付决策：** P0 使用 Tailscale Serve，P1 增加可选的 Tailscale Funnel。用户自部署的 Cloudflare 中继和微信接入暂缓。

## 1. 问题与目标

用户在 Mac 上用 Vela 启动任务后离开电脑，需要通过手机查看进度、回答 Agent 提问、批准具体操作、追加指令或停止任务。每次交互都回到电脑前，会打断长时间任务的推进。

Remote Control 提供适配手机的网页，与桌面端共用同一份会话和执行状态。任务继续在用户的 Mac 上运行。Vela 不运营托管中继，P0 也不要求用户部署云端基础设施。

远程网页的前端界面必须与桌面端保持一致：沿用同一套视觉规范、界面组件、信息层级和操作语义，在窄屏上进行响应式布局适配，不另做一套简化聊天界面。

首版的核心交付结果是：用户在桌面端启动任务，通过不同网络上的已配对手机继续同一个会话，处理真实的待决请求，并在两端看到一致的结果。

## 2. 目标用户与产品边界

主要面向控制自己 Mac 的个人开发者，用户愿意在 Mac 和手机上安装、配置 Tailscale。共享账号、团队角色和操作他人的 Agent 不在首版范围内。

Remote Control 用于控制 Vela 会话，不提供桌面画面串流、任意 macOS 界面的远程操作，也不在浏览器或边缘 Worker 中运行 Agent。现有 Agent 调用的工具保留原有能力与限制。

Mac 必须处于唤醒状态，Vela 主进程必须运行。关闭或隐藏窗口沿用现有桌面后台行为；本功能不新增守护进程、按需唤醒或自动阻止系统睡眠。

## 3. 当前实现与可复用基础

| 现有基础 | 实现位置与用途 |
| --- | --- |
| 共用的运行环境组装 | `packages/runner/src/runtime-host.ts` 导出 `createRuntimeHost`；`apps/desktop/src/main/index.ts` 创建桌面运行环境，注入沙箱、浏览器、凭据和工作区集成。 |
| 会话读取与操作 | `packages/agent/src/runtime.ts` 提供 `listConversations`、`getSnapshot`、`getMessages`、`subscribe`、`prompt` 和 `abort`。运行中追加指令支持现有的 queue、steer 语义。 |

| 桌面前端 | `apps/desktop/src/renderer/themes.ts`、`styles.css` 及 `components/` 下的 `Sidebar`、`Composer`、`ToolCard`、`QuestionCard`、`PlanPanel`、`DiffPane` 等提供现有主题、样式与组件。实现时提取并复用适合浏览器的展示层，通过宿主适配连接远程服务。 |
| 现有桌面行为 | [Agent Inbox 需求](./agent-inbox.md)及其[已实现行为](../features/agent-inbox.md)定义的权限与生命周期约束继续有效。 |
| 独立批量执行 | [Headless Runner](../guides/headless-runner.md) 是使用独立运行数据的单次执行入口，不提供桌面会话同步或本文规划的交互式远程服务。 |

P0 接入正在运行的桌面 Runtime 和现有 Host 服务。不得启动第二个 Agent Runtime 共同读写桌面会话存储，也不得将 Electron IPC 整体暴露为 HTTP 接口。现有桌面 IPC 的发送方校验必须保留。

## 4. 连接方案

| 模式 | 交付阶段 | 手机端要求 | 职责划分 |
| --- | --- | --- | --- |
| Tailscale Serve | P0，推荐方案 | 连接同一 tailnet，且访问规则允许访问 | 用户准备 Tailscale；Vela 提供回环地址上的本地服务、网页客户端、配对和应用层授权。 |
| Tailscale Funnel | P1，明确选择后启用 | 浏览器即可 | 用户准备 Funnel；Vela 在相同应用层认证基础上支持公网可达的访问入口。 |
| Cloudflare Workers + Durable Objects | 暂缓 | 浏览器即可 | 需要单独维护中继、部署模板、凭据及升级流程。 |
| 微信 / OpenClaw 通道 | 暂缓 | 消息客户端 | 需要通道与会话映射，并适配同一套已授权的服务操作。 |

Serve 将本地服务提供给 tailnet 内的设备，遵循其访问规则，代理可以附加用户身份请求头。Funnel 将服务暴露到公网，不附加这些身份请求头。这些是连接方式的属性，不代表设备已获得 Vela 授权。参见 [Tailscale Serve 官方文档](https://tailscale.com/docs/features/tailscale-serve)。

Funnel 目前在官方文档中标为 beta，存在公网监听端口和带宽限制。私有访问失败时，不得静默切换为公网访问。参见 [Tailscale Funnel 官方文档](https://tailscale.com/docs/features/tailscale-funnel)。

拟采用的请求路径：

```text
手机浏览器 -> HTTPS / WSS -> Tailscale Serve 或 Funnel
           -> 127.0.0.1 上的 HTTP / WS -> Vela Remote Server
           -> 现有桌面 Host 服务 -> AgentRuntime
```

网页静态资源与 API 使用同一源。会话持久化和模型凭据继续由现有桌面服务管理。Vela 通过代理提供 HTTPS，P0 不另行设计应用层加密协议。

## 5. P0 范围

| 能力 | 必须实现的行为 |
| --- | --- |
| 配置 | 桌面端 Remote Control 设置、明确的开关、Serve 操作指引、HTTPS 地址配置及连接诊断。默认关闭。 |
| 设备访问 | 桌面确认配对、选择工作区授权范围、持久保存设备记录、会话到期及立即撤销后续访问。 |
| 界面一致性 | 复用桌面主题、样式、组件和交互；宽屏沿用桌面布局，窄屏通过响应式方式呈现同一套界面。 |
| 会话列表 | 显示已授权会话的标题、工作区、真实执行状态、更新时间及待处理数量；按需分页。 |
| 会话详情 | 分页聊天记录、助手回复流式显示、可展开的工具文本、现有文本 diff、最终回复及执行错误。 |
| 发起任务 | 在明确授权给该设备的工作区中新建文本会话，沿用工作区现有权限和默认模型设置发送任务。 |
| 继续任务 | 空闲会话可以发送文本；运行中的会话由用户明确选择现有的 queue 或 steer 行为。 |
| 停止 | 经现有 Runtime 请求取消所选会话的任务，再展示真实的处理结果。 |
| 决策 | 回答或跳过已支持的 Agent 提问，同意或拒绝具体工具请求，并通过现有 Host 校验批准可执行的计划版本。 |
| 恢复连接 | 重连后与权威状态核对同步，不重复提交，也不重放已完成的决策。 |

P0 不包含：文件或图片上传、任意文件系统浏览、产物下载、交互式终端、浏览器或桌面画面串流、远程设置或凭据管理、登记工作区、删除或回退会话、配方阶段控制、富交互 Intelligent UI 执行、原生移动应用、推送通知、离线提交任务、远程唤醒和云端执行。

未支持的内容必须提供可读的文本回退，或明确显示“在桌面端打开”。未支持的决策必须保持待处理，并说明需要在桌面端完成的操作，不能显示为已完成。

## 6. 用户流程

### 6.1 开启与连接

1. 用户打开“设置 → Remote Control”，开启本地服务。Vela 仅监听 `127.0.0.1`，首次选择可用端口并持久保存；后续发生端口冲突时显示可恢复的错误，不静默更换端口。
2. Vela 展示实际本地地址及可复制的 Serve 命令。用户安装、登录 Tailscale，并在 Tailscale 自身流程中完成所需的 HTTPS 或访问规则配置。
3. 用户填入 Serve 生成的 HTTPS 地址。Vela 校验格式，并提供手机端连通性测试指引。本地服务正在运行，不等于外部访问已经可用。
4. 用户在手机上连接 Tailscale 并打开地址。未配对页面仅显示通用配对界面，不返回工作区或会话元数据。
5. 用户在桌面端发起配对，用手机扫描二维码，并在桌面端确认匹配的浏览器请求。只有桌面确认并选定工作区后，配对才完成。
6. 手机获得授权会话，展示授权工作区内的 Vela 会话。

界面中的命令必须使用实际选择的端口。以下仅以 `4318` 为例：

```bash
tailscale serve 4318
```

P0 不负责安装 Tailscale、索取其账号密钥、修改 tailnet 访问规则或现有 Serve/Funnel 路由。配置由用户管理。命令行为参见 [Serve CLI 参考文档](https://tailscale.com/docs/reference/tailscale-cli/serve)。

### 6.2 继续桌面任务

1. 桌面会话中已有正在执行的任务。
2. 用户打开已配对手机并选择该会话。手机上的选择不改变桌面当前会话或工作区。
3. 手机显示聊天记录及实时执行状态。用户追加指令时明确选择 queue 或 steer，不创建并行的主代理运行。
4. 工具审批卡片展示命令或操作、目标、工作区及足够的上下文，让用户能做出与桌面端相同的决策。必要信息被省略或截断时，必须在完整信息可用前禁用同意操作。
5. 用户同意一次，Host 校验请求仍处于待决状态后处理，并更新所有订阅界面。
6. 任务完成，两端均可查看持久保存的聊天记录。

### 6.3 断线与恢复

切换网络或浏览器被挂起时，手机将连接标记为断开，在内存中保留未发送草稿，并禁用新的写操作。不能因此把 Agent 标为已停止，也不能断言 Mac 已睡眠。

重连后，客户端重新认证、核对并同步事件与状态；对提交结果不确定的操作，先按操作 ID 查询，再提供重试。浏览器断线不会停止已接受的任务，也不会自动同意或拒绝待决请求。

### 6.4 撤销访问或关闭功能

桌面设置展示已配对设备的名称、工作区授权、配对时间及最后活动时间。撤销设备后，其授权会话立即失效，事件流关闭，后续请求被拒绝；Host 已接受的工作不会因此被撤回。

关闭 Remote Control 时，关闭监听和事件流，并使授权会话失效。重新开启需要重新配对。正在执行的 Agent 任务继续遵循正常桌面生命周期。Vela 需要说明：即使本地服务已关闭，用户自行配置的 Tailscale 路由仍可能保留。

## 7. 授权与配对要求

以下要求同时适用于 Serve 和 Funnel。加入 tailnet 或知道访问地址，都不足以获得控制 Vela 的授权。

- 只有桌面端可以开启配对窗口、批准浏览器、授予工作区权限、修改授权或撤销设备。已配对手机不能为另一部手机授权。
- 配对挑战值使用至少 128 位密码学随机数，五分钟到期，只能使用一次，并以原子操作完成核销。两端展示一致的确认值。失败尝试必须限速。
- 二维码链接通过 URL fragment 携带短期挑战值。网页客户端先从可见浏览历史中移除该值，再通过请求体交换。配对信息和授权会话密钥不得进入查询参数、日志、分析数据或来源信息。
- 桌面批准后创建不包含可解析授权信息、可撤销的浏览器授权会话，凭据保存在仅适用于当前主机、带有 `Secure`、`HttpOnly`、`SameSite=Strict` 属性的 cookie 中。授权会话 30 天到期；撤销设备或关闭功能可以使其提前失效。续期不能绕过到期规则或桌面授权。
- 设备身份指已授权的浏览器配置文件，不代表经过硬件认证。清除浏览器数据后需要重新配对。用户填写的浏览器或设备名称按不可信展示文本处理。
- 每台设备获得一组明确选择的已登记工作区，不默认选中任何工作区。新增工作区需要桌面端授权；未绑定工作区的会话不在 P0 范围内。服务端对列表、读取、事件、操作和 Inbox 决策统一校验授权范围。
- 远程操作继承目标会话的工具权限，包括已经配置的 Full Access 行为。配对时必须说明该设备可按这些权限提交任务。远程客户端不能提升沙箱权限、配置模型提供方或新增文件系统授权根目录。
- 凭据使用随机值，复用现有桌面设施保护静态存储，且不进入普通诊断信息。凭据保护或授权存储不可用、损坏时，必须拒绝启动服务，不能退化为无认证访问。

## 8. 共享状态、并发与恢复

桌面 Host 始终是权威状态来源。远程读取和操作必须明确指定会话或事项 ID，不能回退到桌面当时恰好选中的会话。

每项远程写操作都带有归属于配对设备的客户端操作 ID、操作类型及请求内容指纹。相同 ID 和内容的重试返回已记录的结果或状态；相同 ID 携带不同内容时拒绝请求。记录在断线后保留，可查询 24 小时。超过该窗口，或服务实例已变化时，客户端不得自动重试结果不确定的操作。

服务必须先记录请求已受理，再返回成功确认。若受理后、结果明确前发生崩溃，恢复时将其标为结果不确定或已中断，并与已有状态核对；不能重放任务、命令、计划批准或工具决策。这是在规定窗口内进行请求去重，不承诺外部副作用恰好发生一次。

| 操作 | 冲突处理要求 |
| --- | --- |
| 启动一轮任务 | Host 按会话串行处理启动请求；桌面和手机同时启动时不能创建两个主代理运行。未成功的请求返回当前状态及冲突原因。 |
| Queue 或 steer | 复用现有 Runtime 指令语义和顺序；运行转为空闲时的竞态由 Host 处理，界面准确展示结果。受配方控制的会话保留原有限制。 |
| 审批或提问 | 使用现有 Inbox 决策路径、请求 ID、预期修订号和客户端操作 ID。第一个有效决策生效，其他客户端收到已处理或版本过期状态。 |
| 执行计划 | 绑定界面展示的确切计划版本。计划已变更、已执行或不再可执行时，旧客户端不能启动它。 |
| 停止 | 指向具体的当前运行实例或代次，不能只指定会话。延迟到达的停止请求不能取消新一轮任务。取消按现有能力尽力完成，不回滚工具已经产生的效果。 |
| 撤销范围或归档 | 执行操作时重新校验授权和可操作状态；旧界面不能保留已撤销的访问能力。 |

事件使用服务实例 ID 和有序游标。重连时先取得与游标边界一致的权威快照，再继续接收事件；游标过期时重新获取快照。缓冲区与发送队列必须有上限。慢客户端通过重连、重新同步恢复，不能无限占用桌面内存。

Vela 重启后生成新的服务实例 ID，关闭旧的实时请求，并遵循现有 Runtime/Inbox 恢复规则。已到期或失效的待决请求不能再操作。持久保存的聊天记录不能被当作此前工具仍在运行的证据。

## 9. 页面与交互要求

### 9.1 与桌面端保持一致

桌面端现有界面是远程网页的设计基准。“一致”包含视觉、组件、内容呈现和交互，不只要求颜色相近。桌面后续调整共用组件时，远程网页应同步获得更新，不能长期维护两套逐渐分化的实现。

| 维度 | 一致性要求 |
| --- | --- |
| 视觉规范 | 复用桌面主题变量、字体层级、间距、圆角、边框、阴影、图标和状态色；不能单独设计远程版配色或消息气泡。 |
| 主题与展示偏好 | 已认证网页只读获取桌面当前主题及共用展示偏好，使用相同规则渲染，包括已支持的自定义主题。桌面修改后同步更新；远程网页不因此获得修改桌面设置的权限。 |
| 导航与信息层级 | 沿用桌面的工作区、会话、聊天区及待处理事项的组织方式、名称和图标。仅展示当前授权范围和 P0 支持的入口。 |
| 消息与工具过程 | 复用用户消息、助手 Markdown、代码块、工具卡片、展开详情、文本 diff、计划和结果状态的展示方式；遵守 P0 内容与安全边界。 |
| 输入与任务控制 | 复用输入区、发送、停止、queue/steer 的状态及反馈；按钮名称、禁用条件、提交含义与桌面相同。仅因终端能力调整键盘和触控操作。 |
| 审批与提问 | 复用桌面的可信审批与提问组件，展示相同的必要上下文、选项、处理结果和过期状态，不能用普通聊天回复替代真实决策控件。 |
| 通用交互 | 加载、空状态、错误、重试、焦点及展开/收起行为沿用桌面规范。配对和连接状态等远程专用界面也使用同一套基础组件。 |

界面一致性不扩大第 5 节定义的功能范围。例如，复用输入区时不开放文件上传，复用消息展示时不执行微应用，复用导航时不开放凭据管理或任意文件浏览。不可用操作应按能力明确隐藏或禁用，不能显示为可执行后静默失败。

### 9.2 响应式布局

- 宽屏浏览器使用与桌面一致的导航和会话布局；在相同视口、主题和内容下，共用区域的视觉与操作应一致。无需复刻 macOS 原生窗口标题栏、交通灯按钮或窗口拖动区域。
- 窄屏将侧边栏收纳为抽屉，主区域显示当前会话；计划、详情等辅助面板按需切换为抽屉或全屏层。调整的是区域排布，不更换内容组件或操作语义。
- 切换抽屉或辅助面板时保留当前会话、滚动位置和未发送草稿。返回会话不触发额外任务，也不改变桌面端当前选择。
- 输入区适配安全区域和软键盘；工具详情、代码和 diff 在自身区域内滚动，不将整页撑出视口。只在悬停时可见的必要操作必须提供触控和键盘入口。

### 9.3 组件复用与宿主适配

优先将现有桌面组件及其样式提取为可共用的前端模块。展示组件通过明确的数据和操作接口使用能力：桌面宿主继续通过 Preload/IPC 访问服务，远程宿主通过已授权的 HTTP/WebSocket 访问相同业务服务。共用组件不能直接依赖 Electron 对象或完整的桌面桥接接口。

不得复制 `apps/desktop/src/renderer` 形成独立维护的远程界面，也不得为了复用而将所有桌面 API 暴露给网页。确实需要平台差异时，仅在布局、输入方式和宿主能力适配层处理，并记录差异。

### 9.4 页面内容与状态

| 界面 | 必须包含的内容 |
| --- | --- |
| 桌面设置 | 功能开关、本地服务状态、配置的 HTTPS 地址、Serve 指引、配对入口、设备授权与撤销、诊断错误。 |
| 配对页 | 通用的未认证界面、桌面确认指引、匹配确认值、到期、拒绝和重试状态。 |
| 会话列表 | 工作区筛选、最近会话、真实执行状态、待处理事项，以及在授权工作区中新建会话的入口。 |
| 会话详情 | 工作区与标题、聊天记录、连接状态、适用时可选择 queue/steer 的输入区、停止、待决卡片及最终结果。 |
| 待处理页 | 仅展示授权工作区内且已支持的待决事项；每项关联原始会话，并反映 Host 的处理结果。 |

网络连接状态与任务执行状态分开显示。界面区分连接中、已连接、重连中、已断开、授权到期、访问已撤销和协议不兼容。断线时展示当前任务状态最后一次确认的时间。

P0 支持 360 CSS 像素宽的视口、至少 44 CSS 像素的触控目标、键盘导航、无障碍标签、明暗主题，以及软键盘弹出后的正常输入。宽代码和 diff 在各自面板内滚动。屏幕阅读器不能被逐个 token 的更新淹没。

所有新增桌面和网页文案按仓库约定提供 `en`、`zh-CN`、`zh-TW`、`ja` 和 `ko` 翻译。本文为需求基线，不是最终界面文案清单。

## 10. 服务与安全边界

远程 API 采用明确的操作白名单：授权会话与配对生命周期、授权工作区和会话读取、共用界面偏好的只读获取与变更订阅、聊天记录及事件读取、新建会话、提交消息、queue/steer、针对具体运行实例的停止、已支持的 Inbox 决策、确切版本的计划执行，以及操作状态查询。不提供通用 RPC 分发、任意 shell 执行或按文件路径读取的接口。

- 仅监听回环地址；只接受已配置的外部主机名与源，以及获准的本地诊断访问。转发请求头不能绕过校验或授权。P0 不将 Tailscale 身份请求头视为应用凭据。
- 远程使用必须经过 HTTPS；对写请求校验 HTTP 来源并提供 CSRF 防护，对 WebSocket 升级校验来源。不开放宽松 CORS。浏览器写操作和流连接接口必须拒绝缺失或非法来源的请求。
- 静态资源与 API 同源，使用严格的 Content Security Policy，将 Agent 输出和 Markdown 按不可信内容渲染。P0 不执行嵌入式 HTML、远程脚本或微应用。
- 返回会话元数据、请求详情、聊天记录或事件前必须验证授权。包含授权会话或任务数据的响应使用 `Cache-Control: no-store`；浏览器不通过 service worker 或 local storage 持久缓存聊天记录。
- 限制请求大小、每个授权会话的连接数、配对与操作频率，提供聊天记录分页和事件流背压。初始限额必须在发布前明确并验证。
- 本地审计记录设备配对与撤销，以及被接受或拒绝的写操作，包含设备 ID、操作类型、目标 ID、时间和结果。不在审计日志中新增原始提示词、工具输出、cookie 值或配对挑战值。现有聊天记录可能包含敏感内容，授权范围内的读取属于预期能力。
- 不能声称撤销访问会删除手机已经查看或复制的数据，也不能声称撤销设备会取消已经受理的任务。

## 11. P1 Funnel 要求

Funnel 复用同一网页客户端、API、配对、授权范围校验和生命周期行为。通过公网访问安全检查后才能发布；P0 仅提供 Serve 指引。

桌面端必须明确说明配置的入口可从公网访问，并由用户主动选择公网模式。Serve 失败时不能自动启用 Funnel，也不能依赖 Tailscale 身份请求头识别公网访问者。

用户在 Tailscale 中配置 Funnel，再在 Vela 中确认地址。现有 Serve/Funnel 配置归用户管理；指引必须说明：将同一监听入口从 Serve 改为 Funnel 会改变其暴露范围，不是在同一监听入口上分别设置两套访问规则。参见 [Funnel CLI 参考文档](https://tailscale.com/docs/reference/tailscale-cli/funnel)。

公网模式必须在手机关闭 Tailscale 的情况下测试。未配对访问者只能加载通用静态页面或配对内容，不能发现用户信息、工作区路径、会话或待决请求。大文件传输和画面串流仍不在范围内。

## 12. 质量目标与可观测性

以下是验收目标，不是已测结果。参考条件为一台 Mac、两个已配对浏览器、包含 1,000 条消息的会话，以及往返延迟不超过 100 ms 的稳定网络。

| 目标 | 验收条件 |
| --- | --- |
| 首屏可用 | 完成认证后，第一页聊天记录和当前状态在三秒内可用，20 次测试至少 19 次达标。 |
| 实时更新 | 保持连接时，Host 状态变化在一秒内展示，达到 p95；不含模型或提供方延迟。 |
| 恢复连接 | 网络恢复可达后，在五秒内完成权威状态同步；以 20 次重连测试的 p95 为准。 |
| 资源占用 | 开启远程功能或保持空闲连接不触发模型调用；历史加载与缓冲区占用受限，不随聊天记录无限增长。背压只影响远程流，不能阻塞 Agent 执行。 |
| 诊断 | 桌面报告本地监听错误、配置地址、最后认证连接及协议错误，不能将本地就绪等同于外部可达。 |

配置成功率、重连延迟、重复请求拒绝和过期决策结果通过本地诊断及受控测试衡量，不依赖托管遥测服务。具体内存、缓冲区和请求限额，以及支持的 Safari/Chrome 版本，必须在性能验收前写入实现计划。

## 13. 交付阶段与验收

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P0-A：Host 服务 | 回环地址上的服务、授权与配对、明确限定的服务操作、共用 Runtime/Inbox 适配，以及操作与事件恢复。 | 授权、并发、持久化和生命周期的定向测试通过。 |
| P0-B：Serve 使用流程 | 与桌面共用组件的响应式网页、桌面配置和设备设置、翻译及 Serve 指引。 | 真实 Mac 与手机在不同网络下完成续聊，不改变桌面当前选择，且界面一致性验收通过。 |
| P0-C：发布准备 | 兼容性、无障碍、资源限额、故障诊断和文档。 | 以下全部 P0 场景通过，完成仓库要求的合并前验证。 |
| P1：公网访问 | 可选的 Funnel 配置及公网访问验证。 | 公网未认证访问、恶意浏览器请求及 Funnel 跨网络检查通过。 |

P0 必须验证以下场景：

1. 通过 Serve 配对手机，只授权一个工作区，继续现有桌面任务，两端状态一致。
2. 在授权工作区中新建会话；拒绝越权新建、猜测 ID、读取聊天记录、订阅事件和提交决策。
3. 配对到期、被拒绝或被重复使用时不产生意外授权。桌面批准前不泄露聊天记录或元数据。
4. 桌面与手机同时启动任务、处理审批、回答提问和执行计划时，仅允许符合条件的操作生效，所有客户端最终状态一致。
5. 写操作确认前后立即断线，重试已知操作不重复执行。延迟停止请求不能影响新一轮任务。
6. 流式输出期间挂起或恢复手机浏览器、切换网络；重连后不丢失已提交消息，也不重复显示。
7. 隐藏桌面窗口、让 Mac 睡眠、退出或重启 Vela、打断持久化；准确显示连接与执行状态，不重放结果不确定的操作。
8. 撤销已连接设备、移除工作区授权和关闭 Remote Control 后，Host 立即终止相应事件访问，并拒绝后续读取和写操作。
9. 拒绝恶意来源、伪造身份或转发请求头、畸形或超限输入、未授权的 WebSocket 升级，以及可执行的消息内容。
10. 对缺少 Tailscale/CLI、不支持的 macOS 客户端发行方式、tailnet 拒绝访问、HTTPS 配置失败、端口冲突、非法地址及协议不匹配，给出可操作的指引。
11. 验证所需语言、窄屏、软键盘、键盘与屏幕阅读器交互、性能目标及慢客户端的资源上限。
12. 使用相同会话内容、执行状态、视口和主题对比桌面与远程网页，检查导航、消息、工具、输入区、审批、提问和计划的截图及操作结果；覆盖明暗主题、自定义主题、流式输出、展开详情和错误状态。允许的差异仅限远程连接信息、能力范围、原生窗口元素及响应式布局。
13. 在至少 360 CSS 像素宽的手机视口、平板和宽屏浏览器中验证同一套组件的布局变化；侧边栏与详情面板收纳、触控入口和软键盘不丢失草稿、滚动位置或关键操作。桌面主题与共用展示偏好变化后，远程网页同步更新，且不会获得设置写权限。

实现将涉及网络、授权、持久化和共享 Runtime 交互，属于高风险变更。先对服务边界做定向测试，再覆盖受影响的桌面、Inbox、Runtime 系统和真实 Electron/浏览器流程。需要合并前验证，或共享代码影响范围要求时，执行全仓检查。本次仅修改需求文档，属于低风险，不要求回归测试。

- 验证支持的 Tailscale macOS 发行方式及 CLI 端口代理能力；不能根据文件服务能力推断兼容性。记录实际测试的版本与发行方式矩阵。
- 在技术设计中确定 API 数据结构、服务实例与操作记录格式、限额、凭据存储及运行代次校验，确保满足上述验收行为。
